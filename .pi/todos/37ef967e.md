# Archive closed pearls on GC instead of deleting them

## Description

Part C. `garbageCollectTodos` currently calls `fs.unlink` on any closed
pearl past the age threshold — the work is simply gone. It should move the
file into an archive directory instead.

## Scope

- `garbageCollectTodos` (`extensions/pearls.ts`, ~line 897): create
  `<todosDir>/archive/` on demand and `fs.rename` the file into it rather
  than unlinking. Handle the cross-device `EXDEV` case with a copy + unlink
  fallback, since a todos dir can sit on a different mount to its parent.
- Name collision in the archive (same id already archived, e.g. after a
  reopen and re-close): suffix or overwrite — suffix is safer.
- Settings: add `archive: true` to the defaults in `DEFAULT_TODO_SETTINGS`
  and `normalizeTodoSettings`, so `archive: false` restores the old
  delete-on-GC behaviour for anyone who wants it. `gc` and `gcDays` keep
  their current meaning.
- Both entry points share this function — the CLI's startup GC in
  `src/cli.ts` and the Pi extension's `session_start` handler (~line 1777) —
  so one change covers both surfaces.

## Read path

`listTodos` uses a non-recursive `readdir` and filters on `.md`, so the
`archive` subdirectory is skipped for free and `list` / `list-all` stay
clean. Two follow-on decisions:

- Should `get <id>` / `path <id>` still resolve an archived pearl?
  Proposal: yes — `findTodoPath` checks the archive directory after the main
  one, so a stale link in a commit message still works. Cheap, and the
  alternative is a confusing "not found" for work that demonstrably existed.
- Should there be a way to list the archive (`list-all --archived`)?
  Proposal: yes, a flag rather than a new command.

## Also worth deciding

- Does `pearls delete` archive too, or stay a true delete? Proposal: stay a
  true delete — the quickstart explicitly frames delete as "for mistakes
  only" — with `--archive` available for anyone who wants the softer
  behaviour. **Question 7 for Hugh.**
- Is `.pi/todos/archive/` committed or gitignored? Proposal: committed, to
  match "todos are committed to the repo"; only `*.lock` stays ignored.
  **Question 6 for Hugh.**

## Note on GC timing

The GC age check compares `created_at`, while the settings doc comment
(line 28) says the threshold is "days since closed_at" and a `closed_at`
field is already written on close. In this repo that means every closed
pearl is already past the threshold and would be collected on the next
non-`--no-gc` invocation. This change makes that safe rather than
destructive; fixing the field mismatch itself is deliberately not in scope
here — flagged for Hugh as a separate call.

## Done when

A closed pearl older than `gcDays` ends up in `.pi/todos/archive/` after a
GC pass, is absent from `list-all`, and is still readable via `get`.
