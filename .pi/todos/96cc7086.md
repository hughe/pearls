# Migrate this repo's own .pi/todos to the new scheme

## Description

The last step, once the rest of the epic has landed: run the migration
against this repository's own backlog so the tool eats its own cooking.

- 25 pearls in `.pi/todos`, all currently closed, all named `<hex>.md`
  (plus the 9 pearls of this epic).
- Run `pearls migrate-filenames --dry-run` first and eyeball the derived
  slugs — several titles are long or contain `/` and `:` (for example
  "TUI: Ctrl+Shift+M filter toggle for memories in /pearls" and "CLI v0.1
  done: list/get/create/update/append/delete/close/reopen/claim/release/dir
  /path"), which makes them a good sanity check on the sanitiser and the
  40-char cap.
- Commit the renames on their own, with no content changes in the same
  commit, so `git log --follow` stays useful on individual pearls.
- Decide at the same time whether the 25 closed pearls should simply be
  archived instead — they are all past the GC threshold, so the first
  non-`--no-gc` invocation after part C lands will move them into
  `.pi/todos/archive/` anyway. Doing it deliberately, in a labelled commit,
  beats having it happen as a side effect of someone running `pearls list`.

Blocked on the other children of this epic.
